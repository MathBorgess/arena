## Conversational workflow addendum (ADR 0003)

The viewer now presents text and native selection only. The companion skill routes `iniciar`, `revisar`, `comparar`, `ramificar`, `aceitar`, `rejeitar`, `voz`, `fontes` and `exportar` as conversational arguments using the host's actual skill invocation. It does not register arbitrary slash commands.

`call --operation OP --input-file FILE` reads a separate private human credential inside the CLI process. The model supplies concrete editorial arguments after the user's explicit instruction for the presented version, never a token or synthetic approval flag. A fixed editorial allowlist excludes membership/credential issuance and verification claims. Agent credentials and identity arguments are refused. Human operation recovery uses the human CLI identity; stale decisions preserve the pending alternative.

Two additional subprocess seam tests cover exact acceptance, idempotent retry, uncertain operation recovery, stale conflict/alternative preservation, agent credential denial and excluded credential operations. The first acceptance test was red because `call` was unavailable, then green after implementation. Three acceptance scenarios additionally verify all seven dimension variations from one voice-pinned base, adversarial-source/lock/approval boundaries and qualitative voice warnings, and independently checksummed portable export with declared session continuity and current source permission checks after database reopen. Existing domain invariants started green; no artificial failure was introduced. The adversarial case correctly allows storing an incompatible pending proposal and blocks its acceptance with `LOCK_VIOLATION`.

Final integration commands/results are recorded in the delivery evidence. Real Codex/ChatGPT installation, account use, embedded rendering and a human conversational decision remain unverified; MCP-only ChatGPT retains proposals until a separate human channel is configured.
