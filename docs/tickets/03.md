## What to build

Show the current artifact alongside the user's existing agent conversation. A compact Portuguese viewer provides selection, feedback, editing and comparison; relevant interactions become durable context readable through MCP. Package it with the MCP and companion skill, preserving the harness as the only conversational surface.

## Acceptance criteria

- [x] MCP Apps-capable hosts render the artifact through a UI resource; compatibility is negotiated and reported accurately.
- [x] Unsupported hosts can open a compact local viewer of the same artifact; no separate chat or editorial platform is introduced.
- [x] Show text, proposed changes, exact revisions and branch differences; allow selecting a passage, attaching a comment, editing and accepting chosen changes through authenticated human actions.
- [x] Persist relevant interactions as typed events with artifact/revision/selection/authorship, retrievable by the agent through MCP.
- [x] Update model context in supporting hosts; distinguish context refresh from an explicit request to continue working.
- [x] Keep voice, locks, sources, stale dependencies and export controls accessible within the artifact workflow.
- [x] Keyboard accessible UI; render source text safely. Verify the interaction→persistent event→agent context path at the confirmed seam, separately from actual harness compatibility.

## Implementation evidence

- `src/http.ts` serves a compact loopback viewer with a separately authenticated human cookie, exact Host/Origin checks, bounded JSON bodies and a restrictive CSP. Agent credentials never authenticate this channel.
- `web/` shares the artifact presentation between the local viewer and the self-contained `dist/artifact-ui.html` MCP Apps resource built by `scripts/build-view.mjs`. UI selection/comment actions persist first, then update host context. Only the explicit review button requests a follow-up message. Embedded edits remain agent-authored pending proposals; decisions, locks, accepted edits and voice approval use the human viewer.
- Browser slices were written red and made green for exploration and partial acceptance; exact passage comment and human edit; agent proposal and model context; authenticated event authorship and explicit message; branch locks/comparison/borrowed suggestion; selected JSON/CSV source preview; immutable voice approval; stale revision/draft preservation; and revocation clearing controlled previews.
- Chromium: `npm run test:ui` — 10 passing browser tests (7 local viewer, 3 SDK AppBridge reference-host). SQLite and HTTP are real; only the host boundary is a fixture. The source preview renders an HTML-shaped reference as literal text. Native controls and keyboard passage selection provide the accessibility path.
- `npm run check` and `npm run build` pass; `npm test` passes 30 integrated Node tests, including the two viewer HTTP security boundaries.
- Codex/ChatGPT installation, native embedding and actual cross-client context delivery remain unverified. SDK capability advertisement and reference-host rendering are technical evidence, not a completed native client pilot. See ADR 0002 and `docs/mcp-clients.md` for the pending native pilot.
