## What to build

Controlled branches, voice memory and authorized sources: observable textual Arena v1 behavior following the recorded specification and shared contract.

## Acceptance criteria

- [x] Branch every dimension from an exact accepted base; enforce locks and mark affected dependencies.
- [x] Preserve concurrent proposals, reject stale acceptance, replay retries after restart.
- [x] Approve immutable voice versions without automatically migrating older branches.
- [x] Import authorized JSON/CSV text exports, revoke/remove sources and members without cross-workspace leakage.
- [x] Export portable context and revised text with source permissions rechecked, deterministic comparison and stable snapshots.

## Validation evidence

Public-domain tests use real SQLite and fictional data. Vertical red→green slices cover branch origin/locks and transitive dependency review; immutable voice approval and readable presented proposals; normalized JSON and quoted multiline CSV imports; artifact selections with exact UTF16 offsets and actual authenticated authors; source revocation/removal across current/historic context, profiles, proposals, comparison, exports and operation recovery; stable list/context/event pagination; owner-only member provisioning/revocation; explicit native-client verification stages; incremental event checkpoints; and adversarial source erasure that cannot rewrite identity metadata.

Accepted text inherits source provenance through its declared dependencies, conservative unknown edges and pinned voice revision. Every response and saved page rechecks current source status. Removal erases local originals, controlled derived text, read snapshots and cached replay text while preserving IDs and audit metadata. External exports remain outside local erasure control. Invitation credentials display once and never persist in operation recovery.

`reviewer` permits reading, feedback, interaction events and authenticated human decisions/reviews; edits, branches, proposals, imports and voice creation require `editor` or owner. Membership administration and native-client verification attestations require the owner. Native provider stages remain owner attestations; technical fixtures do not establish a real client pilot.

`arena.read_events` supplies a snapshot `next_cursor` and an independent `event_cursor` checkpoint consumed as `since_cursor`. Source permission changes create branch events even when the accepted head is unchanged. `arena.record_interaction` always records the delegated actor and an unverified UI-origin hint; human interaction requires separate human authentication.

`npm run check` and the complete available `npm test` suite pass. Ticket 01 supplies restart/concurrency coverage; viewer/MCP/browser integration checks remain with their own tickets.
