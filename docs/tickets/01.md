## What to build

Durable proposal and human decision flow: observable textual Arena v1 behavior following the recorded specification and shared contract.

## Acceptance criteria

- [x] Start an exploration without final text and persist an exact branch revision.
- [x] Submit a proposal through the public domain boundary; feedback does not approve it.
- [x] Only an authenticated human can accept the displayed proposal version into a new immutable revision.
- [x] Real SQLite persistence and atomic mutation/audit/idempotency behavior are exercised through the public seam.

## Validation evidence

Six public-domain tests use real temporary SQLite files, including process-service restart, actor-scoped operation recovery, rejection of changed idempotency arguments, immutable historic revisions, authenticated decision authorship, partial acceptance and stale concurrent proposals. A failed partial acceptance leaves no derived proposal or decision. No internal tables are queried by tests. Audit insertion, state and operation recovery commit in the same transaction; public event inspection follows in ticket 02.

Three vertical red→green slices established durable bootstrap/exploration (missing service → working restart), proposal/feedback/decision (unavailable operation → accepted human revision), and partial acceptance (unselected text incorrectly accepted → only selected dimension accepted). `npm run check` and `npm test` pass. Native-client and viewer checks belong to their integration tickets.
